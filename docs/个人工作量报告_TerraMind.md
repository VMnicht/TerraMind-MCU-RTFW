## 一、项目概述

### 1.1 项目背景

mainboard 是一款面向农业场景的智能机器人嵌入式控制平台。项目目标是从零构建完整的主控固件，实现对以下功能的统一控制：

- **差速轮式底盘**（双 M3508 CAN 总线电机驱动）
- **左右双路播撒器**（各含一个 PWM 舵机 + 一个编码器反馈调速电机）
- **割草装置**（单路 PWM 电调无刷电机）
- **远程指令接收**（通过自定义 UART 通信协议）

### 4.2 面向对象设计关键抽象

#### 4.2.1 串口设备抽象基类 — `SerialDevice`

```
SerialDevice（抽象基类）
├── 封装 UART 句柄
├── 提供中断接收启动接口：startUartReceiveIT()
├── 纯虚函数：handleReceiveData(uint8_t byte) ← 子类实现协议解析
│
├── 子类：cmd_port  ── CmdPort 协议状态机解析
└── 子类：xbox       ── Xbox 手柄数据帧解析
```

**设计亮点**：通过多态让 UART 中断回调将接收的字节分发给不同的协议解析器，新增协议仅需继承 `SerialDevice` 并实现 `handleReceiveData()`，无需修改中断服务函数。

#### 4.2.2 任务处理器抽象接口 — `ITaskProcessor`

```
ITaskProcessor（纯虚接口）
├── virtual void process_data() = 0  ← 任务循环执行体
├── char name[16]                    ← 实例名（调试用）
│
├── TaskManager 管理 10 个任务槽 × 20 个处理器实例
│   支持注册、自定义优先级/周期/栈大小
```

**设计亮点**：FreeRTOS 任务的创建、调度与业务逻辑完全解耦。业务模块只需实现 `process_data()`，由框架负责周期调度。

#### 4.2.3 差速底盘设备类 — `diff_chassis`

```
diff_chassis
├── MechanicalConfig     ── 轮距/轮径/限速/安装方向等机械参数
├── WheelTarget          ── 运动学解算结果（左右轮 RPM）
├── 两种构造模式：
│   ├── 外部传入电机指针（依赖注入，便于测试替换）
│   └── 指定电机 CAN ID（内部管理生命周期）
├── 运动学正解：set_cmd_vel(v, ω) → RPM → CAN 电流指令
├── 运动学逆解：calc_wheel_target_rpm() → 不发送指令（调试用）
├── CAN 同帧打包：send_dual_motor_command() ← 关键设计！
│   └── 同一 CAN 总线上 4 个电机的电流指令必须打包在同一帧
└── 禁用拷贝/赋值（RAII 安全）
```

#### 4.2.4 PWM 电机闭环驱动 — `PwmMotor`

```
PwmMotor
├── HardwareConfig       ── 电机 ID / 编码器参数 / 减速比 / 控制周期
├── SpeedPidConfig       ── Kp/Ki/Kd / 积分限幅 / 输出限幅 / 死区 / 积分分离阈值
├── control_speed(rpm)   ── 设定目标转速
├── 内部闭环：
│   ┌──────────┐     ┌──────┐     ┌──────────┐     ┌──────────┐
│   │ 目标 RPM │ ──► │ PID  │ ──► │ PWM 占空比│ ──► │ 编码器反馈│
│   └──────────┘     └──────┘     └──────────┘     └──────────┘
│         ▲                                              │
│         └──────────────── 转速计算 ◄───────────────────┘
└── 使用 SuperPID（增量式 + 积分分离 + 死区 + 输出限幅）
```

### 4.3 关键设计模式应用

| 设计模式 | 应用场景 |
|----------|----------|
| **策略模式** | `ITaskProcessor` 接口，不同业务逻辑注入不同任务槽 |
| **模板方法** | `SerialDevice` 基类定义中断接收流程，子类实现解析逻辑 |
| **工厂模式** | `diff_chassis` 两种构造方式（外部注入 vs 内部创建） |
| **RAII** | 所有驱动对象禁用拷贝，析构函数自动释放资源 |
| **依赖注入** | BSP 层对象作为参数注入 Driver 层，解耦硬件依赖 |
| **placement new** | `app_main.cpp` 中使用 `alignas` + `placement new` 精准控制对象内存布局 |

## 七、核心技术难点与解决方案

### 7.1 CAN 总线同帧打包机制

**难点**：M3508 电机要求同一 CAN 总线上的 4 个电机的电流控制指令必须打包在同一个 CAN 帧（标准帧 ID 0x200 或 0x1FF）中下发。若左右电机分别独立发送，后发的帧会覆盖先发帧的控制值，导致一侧电机失控。

**解决方案**：
- 底盘类 `diff_chassis` 内部持有两个电机的指针
- `send_dual_motor_command()` 方法将左右轮电流值合并到一个 CAN 帧的正确偏移位置
- 将电机设为 Component 模式，禁止其单独发送指令
- 两个电机 ID 场景处理：
  - `{1,2}` 或 `{5,6}` → 打包到 0x200 帧
  - `{3,4}` 或 `{7,8}` → 打包到 0x1FF 帧
  - 跨帧 ID（如 `{2,3}`）→ 分别在两帧中设对应位置，另一位置填 0

### 7.2 PWM 电机速度闭环控制

**难点**：低成本直流减速电机 + 霍尔编码器，需要实现精确的转速闭环。编码器分辨率仅 52 CPR × 4 倍频 = 208 脉冲/转，经 30:1 减速后需在 2ms 控制周期内完成测速和调节。

**解决方案**：
- 使用 STM32 硬件正交编码器模式（TIM2~5），通过 `__HAL_TIM_GET_COUNTER` 直接读取 16 位硬件计数器
- 控制周期内计算增量脉冲数 → 换算为 RPM
- SuperPID 增量式控制器：通过增量输出而非绝对输出避免积分饱和
- 积分分离：大误差（>50 RPM）时关闭积分项，加快响应；小误差时开启积分消除稳态误差
- 死区（0.5 RPM）：避免稳态抖动
- 输出限幅（0~65535）：防止占空比溢出

### 7.3 自定义通信协议设计

**难点**：UART5 接收端需要从字节流中可靠地提取 19 字节定长帧，需要处理以下异常：
- 字节丢失/插入（帧偏移）
- 噪声干扰（随机字节）
- CRC 校验失败
- 数据长度异常

**解决方案 — 9 状态有限状态机**：
```
WAIT_HEAD_0 → WAIT_HEAD_1 → WAIT_ID → WAIT_LEN → WAIT_DATA
    ↑                                                  │
    │                     ┌────────────────────────────┘
    │                     ▼
    │               WAIT_CRC_0 → WAIT_CRC_1 → WAIT_END_0 → WAIT_END_1
    │                                                  │
    └────────────── 任意非预期值 ──────────────────────┘
                          │
                     CRC 校验失败 ──────────────────────┘
```

**特性**：
- 任何状态收到非预期值立即回退到 `WAIT_HEAD_0`，自动重新同步
- 帧头 `0xFC 0xFB` 双字节降低误触发概率
- 帧尾 `0xFD 0xFE` 双字节额外校验
- CRC-16/XMODEM 覆盖 11 字节数据段

### 7.4 舵机角度标定

**难点**：不同批次舵机的中位脉宽和角度-脉宽斜率存在差异，需精确标定。

**校准参数公式**：
```
角度 = 0° 时 PWM 脉宽 = center_compare（如 1825 ≈ 1.5ms）
角度 = 180° 时 PWM 脉宽 = center_compare + compare_delta * 180 / max_angle_deg
```

通过 `center_compare` 和 `compare_delta` 两个参数即可适配不同舵机。

### 7.5 多定时器外设配置

**难点**：STM32F407VET6 最多 14 个定时器，本项目使用了 12 个（TIM1~TIM14 中除 TIM7 外全部），需要精确分配以避免资源冲突。

**定时器分配策略**：
- 高级定时器 TIM1/8：PWM 输出（带死区控制，适合电调）
- 通用定时器 TIM2/3/4/5：正交编码器接口（硬件解码，不占 CPU）
- 通用定时器 TIM9/10/11/12/13/14：通用 PWM 输出
- 基本定时器 TIM6：FreeRTOS 时基（替代 SysTick）

### 7.6 FreeRTOS 任务管理框架

**难点**：项目中存在多种执行频率要求（500Hz 控制、2Hz 打印、ISR 驱动通信等），需要灵活的任务调度机制。

**解决方案**：`TaskManager` 提供声明式任务注册：
1. 业务模块实现 `ITaskProcessor::process_data()`
2. 通过 `registerTask(taskID, instance)` 注册到指定任务槽
3. 通过 `customize(taskID, priority, delay_ms, stack_size)` 定制调度参数
4. FreeRTOS 启动时自动创建所有已注册任务

## 八、通信协议设计

### 8.1 CmdPort 协议 v2.0 帧格式

```
Byte:  0      1      2       3        4 ~ 14          15     16      17     18
     ┌──────┬──────┬──────┬───────┬───────────────┬──────────┬──────┬──────┐
     │ 0xFC │ 0xFB │  ID  │ 0x0B  │   Data 11B   │  CRC16   │ 0xFD │ 0xFE │
     │ Head │ Head │ 1B   │ Len   │               │  (2B)    │ End  │ End  │
     └──────┴──────┴──────┴───────┴───────────────┴──────────┴──────┴──────┘
帧总长: 19 字节（固定）
```

### 8.2 数据段编码（11 字节）

```
偏移   长度   字段           类型      范围
 0~3    4     linear_speed   float32    -0.35 ~ +0.35 m/s
 4~7    4     angular_speed  float32    -2.0 ~ +2.0 rad/s
  8     1     left_seeder    uint8      0=关, 1=开
  9     1     right_seeder   uint8      0=关, 1=开
 10     1     mowing         uint8      0=关, 1=开
```

|------|-----|
| 算法 | CRC-16/XMODEM |
| 多项式 | 0x1021 |
| 初始值 | 0x0000 |
| 校验范围 | 仅数据段（11 字节） |
